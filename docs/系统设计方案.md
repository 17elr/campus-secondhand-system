# 校园二手交易系统设计方案

## 1. 项目定位

题目建议定为：**基于 Spring Boot + Vue 的校园二手交易系统设计与实现**。

系统面向同一校园内的学生用户，解决闲置物品发布分散、搜索效率低、交易状态不清晰和违规信息缺少管理的问题。系统采用浏览器前端 + REST API 后端 + MySQL 数据库的前后端分离结构。

本方案按毕业设计指导材料控制规模：作品需要提交完整源代码、数据库文件和可运行说明；毕业设计报告不少于 3000 字，查重率不高于 30%，参考文献不少于 5 篇。指导材料给出的时间节点是：2026 年 9 月 30 日前确定题目，2026 年 12 月 20 日前提交作品和初稿，2027 年 1 月 3 日前提交终稿。

## 2. 技术选型

| 层次 | 选择 | 采用理由 |
|---|---|---|
| 后端语言 | Java 17 | 适合展示面向对象、分层和异常处理 |
| Web 框架 | Spring Boot + Spring MVC | 配置少，适合快速搭建 REST 接口 |
| 持久层 | MyBatis | SQL 清晰，方便在论文中说明动态查询和事务 |
| 数据库 | MySQL 8.0 | 成熟、易部署、便于提交数据库脚本 |
| 前端 | Vue 3 + Vite | 与后端解耦，页面开发成本低 |
| UI | Element Plus | 使用现成表单、表格、分页和弹窗组件 |
| 接口请求 | Axios | 统一处理 token、错误和响应格式 |
| 认证 | JWT + BCrypt | 满足登录鉴权和密码安全存储 |

不在第一版加入 Redis、消息队列、微服务、真实支付、WebSocket 和第三方对象存储。它们不影响核心交易闭环，却会增加部署、调试和论文解释成本；后续有性能或功能需求再加。

## 3. 用户角色与功能

### 普通用户

- 注册、登录、修改资料和密码
- 浏览、搜索、筛选商品
- 发布自己的闲置商品并维护状态
- 收藏商品、留言咨询、提交购买意向
- 查看和处理自己的订单
- 举报商品或用户

### 管理员

- 查看数据概览
- 管理用户和用户状态
- 管理商品分类、商品和公告
- 审核/处理举报
- 查看订单和交易统计

### 用户端页面

1. 首页：分类入口、关键词搜索、最新商品和热门商品。
2. 商品市场：分页列表、分类筛选、价格区间、成色筛选、排序。
3. 商品详情：图片、标题、价格、成色、描述、卖家信息、收藏、留言和购买意向。
4. 发布商品：至少一张图片、分类、标题、价格、成色、描述和交易地点。
5. 我的交易：我发布的、我收藏的、我发起的订单、我收到的订单。
6. 个人中心：头像、昵称、校园信息、密码修改。

### 管理端页面

1. 仪表盘：用户数、在售商品数、订单数、待处理举报数。
2. 用户管理：查询、禁用/启用、查看用户发布记录。
3. 商品管理：查询、下架违规商品、恢复商品。
4. 分类管理：新增、编辑、删除分类。
5. 举报管理：查看原因、处理结果和处理人。
6. 公告管理：发布、编辑、下线公告。

## 4. 核心业务规则

- 用户名、手机号或邮箱至少选择一种作为登录标识；密码只保存 BCrypt 哈希。
- 商品状态：`DRAFT` 草稿、`ON_SALE` 在售、`RESERVED` 已预订、`SOLD` 已售出、`OFF_SHELF` 已下架。
- 只有在售商品可以发起订单；卖家不能购买自己的商品。
- 同一商品同一时刻只允许一个有效未取消订单。
- 卖家确认订单后商品进入 `RESERVED`；交易完成后进入 `SOLD`；取消订单时恢复 `ON_SALE`。
- 删除采用逻辑删除，保留订单和举报记录的可追溯性。
- 商品下架、订单状态变化和举报处理都写入操作日志，便于答辩展示。

## 5. 数据库设计

| 表 | 作用 | 关键字段 |
|---|---|---|
| `sys_user` | 用户 | `id`, `username`, `password_hash`, `role`, `status` |
| `goods_category` | 商品分类 | `id`, `name`, `sort_no`, `status` |
| `goods` | 商品 | `id`, `seller_id`, `category_id`, `title`, `price`, `status` |
| `goods_image` | 商品图片 | `id`, `goods_id`, `url`, `sort_no` |
| `favorite` | 收藏关系 | `user_id`, `goods_id`, `created_at` |
| `goods_comment` | 商品留言 | `id`, `goods_id`, `user_id`, `content`, `status` |
| `trade_order` | 购买意向订单 | `id`, `goods_id`, `buyer_id`, `seller_id`, `status` |
| `report` | 举报 | `id`, `reporter_id`, `target_type`, `target_id`, `reason`, `status` |
| `notice` | 公告 | `id`, `title`, `content`, `status`, `published_at` |
| `operation_log` | 管理/关键操作日志 | `id`, `operator_id`, `action`, `target_type`, `target_id` |

关系：一个用户发布多个商品；一个分类包含多个商品；商品拥有多张图片、留言和举报；收藏关系以 `(user_id, goods_id)` 唯一；订单关联商品、买家和卖家。

关键索引：`goods(status, category_id, created_at)`、`goods(title)`、`trade_order(buyer_id, status)`、`trade_order(seller_id, status)`、`report(status, created_at)`。

## 6. REST API 约定

统一前缀 `/api`，统一响应：

```json
{"code": 0, "message": "ok", "data": {}}
```

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/auth/register` | 注册 |
| `POST` | `/api/auth/login` | 登录并返回 token |
| `GET` | `/api/auth/me` | 当前用户 |
| `GET` | `/api/goods` | 分页、分类、价格、成色、关键字查询 |
| `GET` | `/api/goods/{id}` | 商品详情 |
| `POST` | `/api/goods` | 发布商品 |
| `PUT` | `/api/goods/{id}` | 编辑商品 |
| `PATCH` | `/api/goods/{id}/status` | 上下架 |
| `POST` | `/api/goods/{id}/favorite` | 收藏/取消收藏 |
| `POST` | `/api/goods/{id}/comments` | 留言 |
| `POST` | `/api/orders` | 创建购买意向 |
| `GET` | `/api/orders/mine` | 我的订单 |
| `PATCH` | `/api/orders/{id}/status` | 买卖双方更新订单 |
| `POST` | `/api/reports` | 提交举报 |
| `GET` | `/api/admin/overview` | 管理统计 |
| `GET/PUT` | `/api/admin/users` | 用户管理 |
| `GET/PUT` | `/api/admin/goods` | 商品管理 |
| `GET/PUT` | `/api/admin/reports` | 举报管理 |
